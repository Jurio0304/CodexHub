## Highlights

- Fixed redundant file downloads during transfer verification. Remote uploads, downloads, and resume-prefix checks now calculate SHA-256 on the server and return only the digest.
- Kept integrity checks before committing transferred files. Verification supports `sha256sum`, `shasum`, and `openssl`, handles pause/cancel and bounded timeouts, and retains partial files when verification fails.
- Verified a real 100 MiB upload/download round-trip, including pause/resume at 40 MiB in both directions and matching SHA-256 hashes. A separate connection running the same verification script received less than 3 KiB, including a 65-byte digest response.

Remote verification requires SSH command execution with a POSIX shell and a supported hashing tool; prefix checks also require `head` and `wc`. Missing tools or restricted SFTP-only accounts produce an explicit error and preserve the partial file for retry.

## Assets and updates

- Windows x64: `CodexHub_0.5.5_x64-setup.exe`.
- macOS Apple Silicon: `CodexHub_0.5.5_aarch64.dmg` for installation; `CodexHub.app.tar.gz` is for the in-app updater.
- Ubuntu/Debian: `CodexHub_0.5.5_amd64.deb` and `CodexHub_0.5.5_arm64.deb`.
- `latest.json` contains signed updater entries for Windows x64, macOS Apple Silicon, and both Linux architectures. `SHA256SUMS.txt` provides asset checksums.

Updater signatures verify update integrity and are separate from operating-system code signing. The macOS package remains unsigned/ad-hoc; Apple Developer ID signing and notarization are not configured. On first launch, macOS may require Control-click > Open or approval in Privacy & Security.

## 更新亮点

- 修复传输校验导致的额外文件下载。远端上传、下载和断点续传前缀校验均由服务器计算 SHA-256，仅返回摘要。
- 保留校验通过后提交文件的完整性保护，兼容 `sha256sum`、`shasum` 和 `openssl`，支持暂停、取消和有界超时，校验失败时保留临时文件供重试。
- 已完成真实服务器 100 MiB 上传、下载验收，两个方向均在 40 MiB 处暂停并续传成功，完整 SHA-256 一致。单独运行同一校验脚本的 SSH 连接接收量低于 3 KiB，其中摘要响应为 65 字节。

远端校验需要通过 SSH 执行 POSIX shell 命令及可用哈希工具；前缀校验还需要 `head` 和 `wc`。工具缺失或仅支持 SFTP 的受限账户会明确报错，并保留临时文件供重试。
